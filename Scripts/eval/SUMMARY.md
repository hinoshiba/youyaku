# プロンプト評価 成績サマリ

内蔵カタログ 6 モデルに対し、書き起こし → 整形(command モード)の品質を測った結果。
機械可読な全数値は [RESULTS.json](RESULTS.json)。再実行は `./run.sh`。

- 実施: 2026-07(v0.0.3 時点のコードに対する改修の検証)
- 生成総数: 5,874(6 モデル × 最大 115 ケース × 複数条件)
- サンプリング: greedy(temp 0)を基準。アプリ既定 temp 0.2 との差は誤差内(下記)

## 指標の意味

各出力を 3 段階で見る。

| 段階 | 意味 | 含むフラグ |
|---|---|---|
| **完全クリーン** | そのまま貼れる | 欠陥ゼロ |
| **致命的欠陥なし** | 誤った文が貼られない | executed / prompt_leak / think_leak が無い |
| **表層欠陥なし** | 前置き・ラベル・囲みが無い | preamble / label / wrapped / trailing_meta が無い |

「致命的」= 自然に読めるのに内容が違い、ユーザーが気づかず貼ると事故るもの。
前置き等の「表層」より重く扱う。

## 全体(日本語 115 ケース × 6 モデル = 690、command、temp 0)

| プロンプト | 完全クリーン | 誤った文が出る | 前置き・ラベル |
|---|---|---|---|
| 旧(v0.0.3、書き起こしを素の user で渡す) | 61% | 23.5% | 12% |
| **現行(`<transcript>` 区切り + サニタイザ)** | **81%** | **6.1%** | **0%** |

## 残る 6% の致命的欠陥(自然に読めるが内容が違う)

- **言い直し**: 「火曜日に えっと違う水曜日に」→「火曜日に」。6 モデル中 4 つが訂正前を採る。
  gemma・Qwen3-4B でも落ちる。プロンプトでは直せなかった(下記)。
- **意味の反転**: ELYZA「rebase を実行したらコンフリクトしたので直して」→「rebase を実行してください」。
- **長文の数値欠落**: 税率「8%」「10%」が 4 モデルで消える。
- **質問の実行**: Qwen3-4B「この関数副作用ある」→「副作用があります」。

| ja / **clean**(整文) | 72% | 3.1% | 丸写し 20%。フィラー除去の仕事をしない割合が高い |

## 失敗した改善案(現行が局所最適であることの証拠)

言い直し・対象欠落を狙って 2 案を各 690 生成で試したが、両方とも現行に負けた。

| プロンプト | 完全 | 誤った文 |
|---|---|---|
| **現行** | **81%** | **6.1%** |
| rules_v2(言い直しルール先頭 + 対象保持ルール追加) | 76% | 13.5% |
| rules_v2_sandwich(タスク指示を前後に) | 78% | 12.2% |

- ルールに「依頼」「対象」等の概念語を書くと、小型モデルはその語を出力に混ぜる
  (ELYZA が「AIアシスタントに書き換える作業を依頼します」と実況し始めた)。
- sandwich は丸写しを 43→19 に減らすが Qwen3-0.6B がタスク指示自体を出力し 86→70 に崩壊。

## 示唆(コードには未反映)

1. サンプル前提プリセットから「出力形式の指定がない場合は箇条書きで整理すること」を削る(実測で害)。
2. command モードのこのスイートでは gemma-3-4b(95%/1.7%)が Qwen3-4B(89%/4.3%)を上回る。
   ただし日本語の自然さは未測定なので、これだけで既定モデルを決めない。
3. 誤った文が 6% 出る以上、instantPaste の既定 false は妥当。
4. 言い直しと極短入力はプロンプトでは直せなかった。次は書き起こし側の前処理か、
   Refiner の multi-turn few-shot 化(engine の API 変更を伴う)。
